## 2. How the blocks are composed

### 2.1 Sampling cell = the "gate" of thermodynamic computing
Per DTM Fig. 10 [DOCUMENTED, DTM p.25], one cell is made of:

`neighbour states x_j ─XOR s_j→ resistor network (Σ G_j y_j) → V_b → RNG (sigmoidal bias) → latch on clock → broadcast to neighbours`

In this repo the same dataflow is time-multiplexed through one `pbit.v` engine [FPGA-APPROX].

### 2.2 Boltzmann machine / Ising array
- An array of cells on a sparse local graph, with a 2-colour (bipartite) schedule [DOCUMENTED, DTM p.5]. Layers in a deep Boltzmann machine are just subsets of grid nodes (data vs latent) chosen at random [DOCUMENTED, DTM p.24 App. D.2].
- Equivalent software: thrml `IsingEBM` + colour Blocks [DOCUMENTED, thrml/02_spin_models.py:L69-94, L129-160]. torx chromatic PNOT [DOCUMENTED, torx/06_ising_sampling_contrastive_divergence.py:L194-301].
- **Systematic-scan validity:** any fixed visiting order of single-site Gibbs updates leaves the Boltzmann distribution invariant. Within one colour class, sequential updates equal the parallel block update, because same-colour nodes are conditionally independent [INFERRED from DTM p.21 App. C "any two nodes that are not neighbors [can be] updated in parallel"]. This is why our sequential engine reproduces chromatic Gibbs exactly.

### 2.3 Denoising step (DTM)
One DTM step is an EBM over (x^{t−1}, z^{t−1}) with the clamped previous output x^t coupled pairwise to each data node [DOCUMENTED, DTM p.4 Eq. 8, Fig. 3c; p.24 Fig. 9b]. Chaining T such EBMs gives the reverse process [DOCUMENTED, DTM p.4 Eq. 5, Fig. 3b]. The chain can run on distinct circuitry or on the same hardware reprogrammed between steps [DOCUMENTED, DTM p.5].

In hardware terms, clamping x^t adds a per-node bias (Γ_t/2)·x^t_i to h_i. A clamped neighbour contributes a constant to the field [INFERRED from Eq. 11 + Eq. D1]. `rtl/denoise_demo.v` uses exactly this: it rewrites the bias RAM between steps [FPGA-APPROX].

### 2.4 Optimization by annealing
Max-Cut and other Ising-encodable problems: sample while raising β [DOCUMENTED, thrml/03_codon_optimization.py:L303-344]. For Max-Cut, the cut equals Σ_{(i,j)∈E} (1 − s_i s_j)/2 [DOCUMENTED, torx/helpers/_nb09_maxcut.py:L52-60]. Choosing J_ij = −w_ij (antiferromagnetic) makes low energy equal a large cut [INFERRED from the cut formula + Eq. 10].

### 2.5 "Probabilistic ALU" gadgets in the sources
- **Gate circuits (PSC):** layers of gates with disjoint supports run in parallel, and layers compose in series [DOCUMENTED, SDP p.5 Eqs. 14-16]. Mixture-of-Gaussians = ancilla pdit + controlled shift + discard [DOCUMENTED, SDP p.6 Eq. 27].
- **Diffusion / random walks:** one PSWAP per edge, Trotterized, gives graph heat flow [DOCUMENTED, SDP p.7, p.10; torx/02_random_walks_on_graphs.py:L136].
- **Integer factorization by heat diffusion:** discrete-time heat kernel on a Cayley graph [DOCUMENTED, HF p.1, p.5]. The physical primitive is an RC network implementing exp(−tL/C) [DOCUMENTED, DF p.63 Eq. 17.1]. The small-FPGA prototype is an exact integer update c_{t+1}(x) = 2c_t(x) + c_t(x b^{2^t}) + c_t(x b^{−2^t}) [DOCUMENTED, DF p.71 Eq. 19.4]. The author describes it as "a verification platform, not a fast large-integer factoring machine" [DOCUMENTED, DF p.71]. **Not built here.** It is deterministic integer arithmetic, not a p-bit block, and the monograph's own RTL is unsynthesized [DOCUMENTED, DF p.75].
- **Logic gates via energy composition (AND/OR/NOT):** mentioned [DOCUMENTED, BP p.3], but no energy coefficients are given in data/ [NOT IN SOURCES]. We built them anyway with the standard Ising gadgets (plus a brute-forced XOR with one auxiliary p-bit), composed them into a full adder and a 2×2 multiplier, and ran the multiplier backwards to factor 6, 3, 9 and 4 on the RTL. See docs/04 §3-4 (pictures) and docs/05 (results). The coefficients remain ours, not the papers'.
